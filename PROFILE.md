# Addis Eats Performance Profile

## Scope

Day 34 hardens the Day 33 application without adding optimizations that are
not tied to an observed behavior.

## Before

The checkout and receipt modules were imported statically from `App.jsx`.
The production build therefore put checkout code in the main JavaScript bundle.

Measured with `npm run build` before lazy loading:

- Main JavaScript bundle: approximately 249.56 kB
- Separate checkout chunk: none
- Checkout code downloaded on the home page: yes

## Change

`Checkout.jsx` and `Receipt.jsx` now use `React.lazy` and render behind a
`Suspense` skeleton. The menu and cart are wrapped in separate error boundaries,
and the dish dialog is rendered with a portal so it escapes card overflow.

## After

Measured with `npm run build` after the change:

- Main JavaScript bundle: approximately 246.73 kB
- Separate checkout/receipt lazy chunks: generated by Vite
- Checkout code downloaded on the home page: no; it loads when `/checkout` is visited

The main bundle is smaller because checkout is no longer part of the initial
route payload. The remaining optimization is justified by the route-level
bundle split rather than by an assumed improvement.

## Behavior Checks

- `/menu?fail=menu` shows the menu fallback while the shared header and cart remain available.
- `/cart?fail=cart` shows the cart fallback while the menu route remains available.
- `/checkout` displays the Suspense skeleton while the lazy chunk loads.
- Dish dialogs use `createPortal`, close with Escape, trap Tab focus, and return focus to the trigger.
